01

Understand the context trade-off

A large catalog can consume context and complicate selection. Search defers schemas and discovers relevant tools, at the cost of a search round-trip. This app uses 90 real local handlers across three SDK MCP servers.

02

Compare five environment settings

Run unset, true, false, auto and auto:5. The TypeScript env object spreads inherited variables and removes an inherited search override for the unset experiment. A requested value is configuration, not proof of actual activation.

03

Observe discovery and actual execution

Inspect real ToolSearch requests, native tool results and completed handler calls. A tool listed at initialization is not proof that its full schema occupied the prompt or that it executed.

04

Measure context with the real SDK

After each result, keep the streaming query open and call getContextUsage with detail full. Compare totalTokens and category kind used versus deferred. Catalog bytes are not tokens; post-result measurements include different conversation messages.

05

Improve names and descriptions

The discovery experiment replaces query_course_notes with search_course_notes, adds detailed keywords and a searchHint. Both return the same local lesson record. One successful run does not prove a statistical accuracy improvement.

06

Keep a critical tool loaded

The always-load experiment pins only catalog_status with alwaysLoad true. Other schemas remain eligible for discovery. The model then calls the status tool and the appropriate course-notes tool.
